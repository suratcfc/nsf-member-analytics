# กอช. · แดชบอร์ดสมาชิกใหม่

แดชบอร์ดสรุปข้อมูลสมาชิกใหม่ของกองทุนการออมแห่งชาติ แบบ interactive เปิดด้วยเบราว์เซอร์ได้ทันที ไม่ต้องติดตั้งอะไร

**ดูหน้าเว็บ:** https://suratcfc.github.io/nsf-member-analytics/

ธีม ฟอนต์ (Kanit) และโลโก้ อิงตาม [nsf-newmember-dashboard](https://suratcfc.github.io/nsf-newmember-dashboard/)

---

## โครงสร้างไฟล์

```
index.html          หน้าแดชบอร์ด — โครงหน้า สไตล์ และตัวเรนเดอร์ทั้งหมด
data/
  └── 2569.js       ข้อมูลปีปฏิทิน 2569  ← แก้ไฟล์นี้เวลาอัปเดต
assets/
  └── logo.png      โลโก้ กอช.
README.md
```

**หลักการ:** `index.html` ไม่มีตัวเลขฝังอยู่เลย ตัวเลขทั้งหมดอยู่ใน `data/2569.js` เท่านั้น เวลาอัปเดตจึงแก้ไฟล์เดียว ไม่ต้องแตะโค้ด

## วิธีอัปเดตข้อมูล (รอบถัดไป)

### 1. ดึงตัวเลขใหม่จาก Tableau

**นิยามที่ต้องใช้** — ตรงกับ calculated field ในไฟล์ workbook `Working` (ฝ่ายทะเบียนสมาชิก)

| รายการ | สูตร |
|---|---|
| สมาชิกใหม่ | `COUNTD(INVESTOR_CODE)` where `TYPE IN ('1','3')` |
| เงินนำส่งงวดแรก | `SUM(PRINCIPLE)` ของรายการชุดเดียวกัน |
| เงินนำส่งงวดถัดไป | `SUM(PRINCIPLE)` where `TYPE IN ('2','4')` |
| กรองช่วงเวลา | ใช้ `TR_DATE` เท่านั้น — **ห้ามใช้ `REG_TR_DATE`** |
| Data source | `VIEW_BI_DS` (LUID `08ae6a5c-4b0d-418f-8881-95a11ed5ab28`) |

ตัวอย่าง payload ของ VizQL Data Service:

```json
{
  "datasource": { "datasourceLuid": "08ae6a5c-4b0d-418f-8881-95a11ed5ab28" },
  "query": {
    "fields": [
      { "fieldCaption": "TR_CHANNEL_NAME", "fieldAlias": "name" },
      { "fieldCaption": "INVESTOR_CODE", "function": "COUNTD", "fieldAlias": "members" },
      { "fieldCaption": "PRINCIPLE", "function": "SUM", "fieldAlias": "money" }
    ],
    "filters": [
      { "field": { "fieldCaption": "TYPE" }, "filterType": "SET", "values": ["1", "3"] },
      { "field": { "fieldCaption": "TR_DATE" }, "filterType": "QUANTITATIVE_DATE",
        "quantitativeFilterType": "RANGE", "minDate": "2026-01-01", "maxDate": "2026-12-31" }
    ]
  }
}
```

### 2. แก้ `data/2569.js`

เปลี่ยนเฉพาะตัวเลขในแต่ละบล็อก โครงสร้างต้องคงเดิม

| บล็อก | ใช้ทำอะไร |
|---|---|
| `meta` | ช่วงเวลา วันที่ข้อมูล ข้อความในหัวเรื่องและ footer |
| `totals` | ตัวเลขใหญ่บนสุด (คน / เงิน / มัธยฐาน / ค่าเฉลี่ย) |
| `followThrough` | แถบผู้ที่ส่งเงินงวดถัดไปแล้ว |
| `memberDrive` | กราฟเป้าหมายและตารางสมาชิกเพิ่มรายสัปดาห์ แยกตามชื่อแคมเปญ |
| `months` | กราฟรายเดือน — ใส่ `partial: true` ในเดือนที่ข้อมูลยังไม่ครบ |
| `channels` `channelTypes` `campaigns` | ช่องทาง ช่องทางที่มา แคมเปญ |
| `ages` `occupations` `regions` `provinces` | ช่วงอายุ อาชีพ ภูมิภาค จังหวัด |
| `genders` `statuses` | เพศ และสถานะสมาชิก |
| `findings` `caveats` | การ์ดข้อสังเกต และรายการข้อควรระวัง |

ทุกแถวใช้รูปแบบเดียวกัน:

```js
{ name: "ชื่อที่แสดง", members: 12345, money: 678910 }
```

- `name` — ชื่อสั้นที่ใช้แสดงผล (ใส่ `full` เพิ่มได้ถ้าอยากให้ tooltip แสดงชื่อเต็ม)
- ค่าเฉลี่ยต่อคนคำนวณให้อัตโนมัติ ไม่ต้องกรอก
- สัดส่วน % คำนวณให้อัตโนมัติ ไม่ต้องกรอก
- ลำดับใน array คือลำดับที่แสดงในกราฟแท่ง (เรียงมากไปน้อยไว้จะอ่านง่ายที่สุด)
- `findings[].tone` รับค่า `warn` (แดง) · `good` (เขียว) · `neutral` (ทอง)

ใน `memberDrive.weekly` ให้เพิ่มหนึ่งแถวต่อสัปดาห์ และกรอกจำนวนที่เพิ่มขึ้นใน `values` ตาม key ของแคมเปญ ส่วนยอดที่ทราบเฉพาะยอดรวมแต่ยังแยกแคมเปญไม่ได้ ให้ใส่ไว้ใน `memberDrive.pending` โดยไม่เดากระจายลงแคมเปญ กราฟและยอดรวมจะคำนวณต่อให้อัตโนมัติ

### 3. ตรวจก่อนอัป

เปิด `index.html` ด้วยเบราว์เซอร์ตรงๆ ได้เลย (ไม่ต้องมีเซิร์ฟเวอร์) แล้วเช็ก:

- ตัวเลขใหญ่ตรงกับ Tableau
- กดสลับ **จำนวนคน / เงินงวดแรก / เฉลี่ยต่อคน** แล้วกราฟเปลี่ยนตาม
- แถวรวมท้ายตารางบวกได้ตรง

### 4. อัปขึ้น GitHub

```bash
git add -A
git commit -m "อัปเดตข้อมูลถึง <วันที่>"
git push
```

GitHub Pages จะอัปเดตหน้าเว็บเองภายใน 1–2 นาที

## สิ่งที่ยังไม่ยืนยัน

ตัวเลขทั้งหมดถูกต้องตามที่ Tableau ให้มา แต่ **ป้ายกำกับ** 2 ชุดนี้เป็นการตีความ ยังไม่ได้ยืนยันกับเจ้าของข้อมูล — ควรเช็กก่อนนำไปใช้เป็นทางการ

- **`TR_CHANNEL_TYPE`** รหัส 1–6 (เคาน์เตอร์ / ตู้เติมเงิน / แอป / โมบายแบงก์กิ้ง / ตัวแทน)
- **`MEMBER_STATUS`** รหัส A · A3 · C · Q · R1 · R3 — อนุมานจากการไล่ดูฟิลด์ `วดป_ลาออก` และ `วดป_เสียชีวิต`

ส่วนตารางถอดรหัส **`TYPE`** ยืนยันแล้ว มาจาก calculated field `ประเภทการทำรายการ` ในไฟล์ workbook `Working` โดยตรง

## ข้อมูลส่วนบุคคล

ไฟล์ในรีโปนี้เป็น **ตัวเลขสรุปเท่านั้น** ไม่มีข้อมูลระดับบุคคล

`VIEW_BI_DS` มีฟิลด์ `CITIZEN_ID` · `FULLNAME` · `EMAIL` · `เบอร์โทรศัพท์` · `LINE_ID` · `FULLADDRESS` — **ห้ามนำมาใส่ในรีโปนี้ไม่ว่ากรณีใด** เพราะเป็นรีโปสาธารณะ ถ้าต้องทำรายงานระดับบุคคลให้ทำนอกรีโปนี้

## การอัปเดตอัตโนมัติ

Dashboard แยกความสดของข้อมูลเป็น 2 ระดับเพื่อไม่ผสมตัวเลขคนละรอบประมวลผล:

- **ยอดสมาชิกใหม่ล่าสุด** ใช้ `https://dashboard.nsf.or.th/`
- **รายละเอียดและตัวเลขทางการเงิน** ใช้ Tableau `VIEW_BI_DS` ตามวันที่ใน `meta.detailAsOf`

เตรียมสคริปต์ `scripts/update-latest-members.mjs` และ Workflow `.github/workflows/update-latest-members.yml` ไว้แล้ว แต่จากการทดสอบวันที่ 23 ส.ค. 2569 พบว่า `dashboard.nsf.or.th` ไม่รับการเชื่อมต่อจาก GitHub-hosted runner (connect timeout) จึงไม่เปิดตารางเวลารายชั่วโมงเพื่อป้องกันงานล้มเหลวซ้ำ

หากต้องการเปิด near real-time ให้ติดตั้ง GitHub self-hosted runner ในเครือข่ายที่เข้าถึง `dashboard.nsf.or.th` ได้ ติดป้าย runner ว่า `nsf-network` แล้วเพิ่ม schedule กลับใน Workflow สคริปต์ใช้เฉพาะข้อมูลสรุปสาธารณะ ไม่ใช้รหัส Tableau และไม่แตะข้อมูลระดับบุคคล
